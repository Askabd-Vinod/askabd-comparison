# Documentation Standard

## Purpose
This document defines how engineering documentation should be written and maintained for the platform.

## Scope
Applies to all repository documentation, architecture notes, operational guides, and change records.

## Principles
- Documentation first
- Keep documentation current and practical
- Make intent and decisions clear
- Prefer concise and structured content

## Standards
- Use clear headings and short sections.
- Document purpose, scope, assumptions, and constraints.
- Keep instructions actionable and specific.
- Update docs when behavior or workflow changes.
- Prefer examples and checklists over dense prose.

## Best Practices
- Keep documentation close to the systems it describes.
- Link related documents and references.
- Use consistent terminology across the repository.

## Examples
- Good: A README explains prerequisites, run steps, and expected outcomes.
- Poor: A document that describes a process vaguely without action steps.

## Do
- Maintain docs as living artifacts.
- Use enterprise-quality writing.

## Don't
- Leave stale documentation in place.
- Duplicate the same guidance in multiple locations without clear ownership.

## Review Checklist
- [ ] Purpose and scope are clear.
- [ ] Instructions are accurate and current.
- [ ] Terminology is consistent.
