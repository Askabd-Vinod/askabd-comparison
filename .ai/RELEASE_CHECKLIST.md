# Release Checklist

## Purpose
This checklist defines the quality bar for releases of the AskABD platform.

## Scope
Applies to all production and pre-production release activities.

## Principles
- Quality before release
- Controlled rollout
- Observability and recovery
- Stakeholder readiness

## Standards
- Confirm the release scope, version, and approvals.
- Verify tests, builds, migrations, and deployment readiness.
- Review release notes and rollback instructions.
- Monitor the release after deployment.

## Best Practices
- Use a pre-release validation window where practical.
- Coordinate communications for user-impacting changes.
- Record defects or issues discovered during release.

## Examples
- Good: A release includes a tested version, release notes, and rollback plan.
- Poor: A release goes live without validation or communication.

## Do
- Validate the release in a safe environment first.
- Keep rollback steps ready.

## Don't
- Release without confirming health and readiness.
- Skip documentation for user-visible changes.

## Review Checklist
- [ ] Release scope and version are clear.
- [ ] Testing and deployment steps are complete.
- [ ] Rollback and monitoring are prepared.
