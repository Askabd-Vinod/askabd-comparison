# AskABD API — TypeScript Debt Register

**Baseline:** `npm run build` (`tsc`, from `apps/api/`) — **43 errors, 13 files.** Confirmed to genuinely block the API's own configured build script (not just `tsc --noEmit`). None of these were introduced by the reliability-hardening milestone (verified: identical file/error set before and after that work).

**tsconfig relevant flags:** `strict: true`, `noUnusedLocals: true`, `noUnusedParameters: true`, `noImplicitReturns: true`, `noUncheckedIndexedAccess: true`. The last flag — which types *all* indexed access (arrays, `Record`) as `T | undefined` — accounts for most of the non-trivial errors here; it wasn't loosened to fix them.

## Real findings surfaced during this pass (not fixed — out of scope for a TS-debt closure)

These are genuine product/behavior observations discovered while tracing *why* each variable was unused — flagged per the instruction to not blindly delete without understanding intent, not silently acted on:

1. **Audit trail gaps**: `actor` is accepted but never persisted in `acknowledgeFinding`/`resolveFinding` (continuous-optimization), `updateProblem`/`updateStatus` (problem-universe), `defineTargetState` (gap-analysis), `transitionException` (compliance). None of these tables record *who* made the change.
2. **Unwired validation lists**: `VALID_TXN_STATUSES`, `PAYMENT_METHOD_TRANSITIONS`, `VALID_DOMAINS` are all defined but never checked against anywhere — the transition/domain validation they imply doesn't actually happen.
3. **Discarded recommendation text**: `generateRecommendations()` in gap-analysis-service.ts computes a human-readable title and action for each auto-generated recommendation, then stores neither — only a generated ID.
4. **Dead connector re-check**: `verifyDefectResolution()`'s `'connector'` category branch in defect-detection-service.ts queries connector status and never inspects the result before falling through to an unrelated fallback check.

None of these were changed. They're documented here as a byproduct of this audit, for a future product/reliability decision — not implied by "fix the build."
